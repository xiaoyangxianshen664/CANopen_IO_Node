## 构建与现有测试

首次重新构建发现 `co_types.h` 末尾重复 `#endif`，移除多余的一条，保留其余内容及原文件字节编码。

随后 8/11 测试通过，`od_device`、`od_signed`、`od_eds` 失败。当前 `co_od.c` 未处理已经在头文件和实际对象表中使用的 INTEGER16：类型长度函数缺少分支，写入解码只按无符号解释。补充 INTEGER16 的 2 字节长度，使用 int64_t 暂存解码值，并将 0x8000～0xFFFF 减去 0x10000 后再比较上下限。没有修改测试期望来掩盖失败。

修复后执行：

```text
cmake --build build
ctest --test-dir build --output-on-failure
100% tests passed, 0 tests failed out of 11
```

构建沿用 Release/C11 和 `-Wall -Wextra -Wpedantic -Werror`。这是本日重新编译后的验证结果，不是旧可执行文件的结果。

## 第三方 EDS 离线导入：通过

采用独立第三方库 python-canopen 2.4.1（依赖 python-can 4.6.1），安装在 `build/eds-third-party`，不改变项目核心构建依赖。复验脚本为 `tests/verify_eds_third_party.py`，使用第三方 `import_od()` 导入 EDS，并创建离线 `RemoteNode`。

```text
python -m pip install --target build/eds-third-party canopen==2.4.1 python-can==4.6.1
python tests/verify_eds_third_party.py build/tests/test_co_device_od.exe eds/CANopen_IO_Node.eds build/eds-third-party
```

本机使用 CMakeCache 中记录的可执行 Python 路径。由于联网安装目录的沙箱读取权限限制，第三方检查在允许读取该目录的环境运行；不连接 CAN 总线。

结果：Node-ID 1、2、127 均成功导入 13 个索引、35 个实际变量条目，EDS 类型号、字节长度、权限、默认值、下限、上限均与 C 程序 `dump` 输出一致，三个离线 RemoteNode 均成功创建。

这完成了“第三方解析库离线导入”验证，不等于图形主站工具导入、CiA EDS 一致性认证或 STM32 总线互通。python-canopen 的解析器也不代替完整 CiA 306 校验器。

### 新发现的待核对项

CiA 401-1 v3.1.0 官方 Scope 明确写有：

> All TPDOs are triggered by change-of-state. Therefore, default TPDOs containing analog inputs are disabled.

当前项目 TPDO2 默认 COB-ID 为 `0x40000280 + Node-ID`（bit31=0，启用），事件周期 100 ms。此配置与上述标准默认行为存在差异线索，需要确定采用的规范版本、是否作为设备自定义默认配置，以及所需声明。

官方介绍还指出，厂商自定义默认 PDO 集通过 Device Type 的 M 位指示。此说明位于新版本介绍上下文中，必须查适用版本正文后，才能判断本项目固定 PDO 映射是否需要设置该位；不能直接根据摘要修改 Device Type。`0x00070191` 暂不冻结。

本次没有擅自修改对象表默认值、PDO 映射或 EDS 来追随摘要。

## 正式冻结如何完成

2. 核对 INTEGER16、Device Type/M 位、PDO 默认启用状态与映射、必要对象、权限及 EDS 字段；记录条款依据，处理发现的差异。

## 同日补充：用户已提供 CiA 301 和 401-1 正文

已确认本地 `协议文档/301v04020008.pdf` 为 CiA 301 v4.2.0（2011-02-21，158页）；`协议文档/401_1v03010008.pdf` 为 CiA 401-1 v3.1.0（2013-02-12，132页）。CiA 306-1 尚未提供。用户截图显示受会员限制的是 CiA 401-C v1.0.0，不是 CiA 306-1。

本次为关键条款初查，并未完成两份正文的全部一致性核验：

- CiA 401-1 8.4.2，第90页，表130/131：0x6401 类型明确为 INTEGER16，通道为 ro；同时要求不足16位的值左对齐，低位补零。当前直接导出 0～4095 ADC 原始值，不能仅因类型正确就视为满足该表示规则。需设计单极性量程与符号位处理，不能未经分析直接左移后当成有符号正数。
- 6.2.8，第17～18页，表18：默认禁用的是 0x6423 模拟量中断源；TPDO2 的默认 COB-ID 允许 0x40000280 + Node-ID。此前从官网摘要推断 COB-ID 应禁用不成立，以正文修正。表18规定 event timer 默认0，当前100 ms仍是待处理差异。
- 6.2.1，第8～9页，图1/表2：DI、DO、AI分别是 bit16、17、18；M为 bit23。0x00070191 的功能位组合正确，但 M=0 表示预定义通用映射，仍须结合全部相关条件核验，不能据此宣称整个设备符合 CiA 401。
- 6.2.8及表19/20，第19～20页：模拟量默认映射按已实现通道决定，前两项为0x64010110和0x64010210。固定映射本身并不能推出必须设置M位。

已渲染并核对第18、90页表格。此次只记录依据，未修改对象默认值、AI表示方式或EDS。后续需继续检查必需对象、0x6423等条件项以及通信行为，再确定修正方案。
## 同日补充：CiA 306 正文初查

用户新增 `协议文档/306v01030006.pdf`，封面确认 CiA 306 v1.3.0，2005-01-01，共26页；不是官网目录中的 CiA 306-1 v1.4.0。以下依据限定于已取得版本，不声称覆盖新版差异。

已读第4章相关条款，并渲染核对第12、15页：

- 4.3，第10页：允许 `$NODEID` 开头加数值偏移，当前 COB-ID 公式符合该形式。
- 4.4，第10～11页：本版明确要求 `EDSVersion=4.0`；当前文件版本字段和日期时间格式符合所读规则。
- 4.5，第12页：Granularity=0 表示映射不可修改，1～64表示可用映射粒度。本项目固定映射不可修改，但 EDS 声明 Granularity=8，发现明确待修正项，应改为0并增加静态检查。
- 4.6.3.1，第13页：MandatoryObjects 包括1000、1001、1018；其他通信及设备配置对象列入OptionalObjects；当前对象列表分类符合这部分规则。
- 4.6.3.2，第14～15页：SubNumber 统计已实现子项（包括00，不计FF），不是最高子索引。1800/1801的子项0、1、2、3、5共5项，当前SubNumber=5正确。
- PDOMapping 表示对象是否可映射，不能与“是否允许修改整个PDO映射表”混为一谈；固定映射的实际I/O子项仍可标为1。
