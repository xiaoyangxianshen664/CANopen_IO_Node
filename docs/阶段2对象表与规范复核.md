## 与阶段 0 草案的修正

1. `0x6401:01/02` 使用 **INTEGER16**，EDS DataType 为 `0x0003`。旧草案 UNSIGNED16 改正；应用仍只提供 ADC 原始值 0～4095，两字节、小端、PDO 映射长度均不变。通用 OD 增加 `CO_OD_INTEGER16`，范围字段改为 `int64_t`，既容纳有符号 16 位，也保留完整 UNSIGNED32 范围。内部枚举值不能直接当作 EDS 类型编号。
2. Device Type 暂定 `0x00070191`：低 16 位 `0x0191=401`；高 16 位 `0x0007` 表示数字输入、数字输出和模拟输入。该数值须在原文核验后正式冻结。
3. `0x1800:01/0x1801:01` 使用 `0x40000180+Node-ID`、`0x40000280+Node-ID`，bit30=1 表示不接受 RTR。bit31=0 表示 PDO 有效，bit29=0 表示标准帧。阶段 6 提取实际 CAN-ID 时必须去掉配置标志，不能将整个值直接填入 `can_frame_t.id`。RPDO 为 `0x200+Node-ID`。
4. 0x1800/0x1801 的最大子索引为 5；实际子项是 0、1、2、3、5。因此 EDS `SubNumber=5`，不是 6。04 不实现。
5. 0x2000 仍仅为预留，不进入实际表和 EDS。

## 身份与初值

默认 Identity：Vendor-ID=0（**未分配的开发占位**），Product code=1，Revision=0x00010000，Serial=0（开发设备不保证唯一）。它们不能用于宣称注册厂商或量产设备身份。

应用可给 `co_device_od_init()` 传入 `co_device_identity_t`。更换身份时须同步 EDS 的 Identity 默认值和 DeviceInfo；当前提交的 EDS 对应默认开发身份。

DI、DO、AI、错误寄存器初始为 0。心跳周期为 1000 ms。TPDO1/2 inhibit time 均为 0；event timer 分别为 0、100 ms。周期参数均允许 0～65535，0 关闭相应周期触发；本阶段只存参数，不启动任何定时器。

## 实际条目

| 索引 | 子索引 | 内容与权限 |
|---|---|---|
| 1000 | 00 | U32 ro，Device Type |
| 1001 | 00 | U8 ro，错误寄存器；应用接口禁止保留 bit6 |
| 1017 | 00 | U16 rw，心跳周期 ms |
| 1018 | 00、01～04 | U8 ro 数量4；四项 U32 ro 身份 |
| 6000 | 00、01 | U8 ro 数量1；U8 ro 四路逻辑 DI，0～15 |
| 6200 | 00、01 | U8 ro 数量1；U8 rw 四路 DO 命令，0～15 |
| 6401 | 00、01、02 | U8 ro 数量2；两路 INTEGER16 ro AI，0～4095 |
| 1400 | 00、01、02 | U8 ro 最大子索引2；U32 ro RPDO1 COB-ID；U8 ro 传输类型255 |
| 1600 | 00、01 | U8 ro 映射数1；U32 ro `0x62000108` |
| 1800、1801 | 00、01、02 | U8 ro 最大子索引5；U32 ro TPDO COB-ID；U8 ro 类型255 |
| 1800、1801 | 03、05 | U16 rw inhibit time（100 us）、event timer（ms）；仅 Pre-operational 可写 |
| 1A00 | 00、01 | U8 ro 映射数1；U32 ro `0x60000108` |
| 1A01 | 00、01、02 | U8 ro 映射数2；U32 ro `0x64010110`、`0x64010210` |

`ro/rw` 是经对象字典访问的权限。应用更新 DI/AI 不经过主站写接口，所以只读输入仍能随采样改变。PDO 可映射标志仅给四个实际 I/O 子项；Heartbeat、身份、PDO 配置本身均不可映射。

## 使用和生命周期

```c
co_device_od_t device = {0};
const co_od_entry_t *entry = NULL;
uint8_t data[2];

co_device_od_init(&device, 1, NULL);
co_device_od_update_inputs(&device, 3, 1234, 4095);
co_od_find(&device.table, 0x6401, 1, &entry);
co_od_read(entry, data, 2); /* 示例省略逐步错误处理；实际调用须检查返回值 */
```

`device` 拥有条目数组和 RAM 数据；初始化建立 `entry.user → fields[i]` 的连接。初始化后**不得按值复制或移动**，必须比使用它的服务活得更久。所有访问须串行（将来由单协议任务或锁保证）。自动变量必须先初始化，不得把未初始化的栈对象交给查询接口。头文件公开成员是为了静态分配，不代表调用方可以绕过检查直接改它们。

`co_device_od_update_inputs()` 在所有参数通过范围检查后一起提交，DI 的低四位是逻辑有效状态；低电平按下到逻辑 1 的转换放在未来 GPIO 适配层。DO 通过对象写入回调更新 RAM，应用用 `co_device_od_get_outputs()` 获取命令，尚不操作 GPIO。

`co_device_od_get_heartbeat()` 返回周期和成功写次数。同值写入也增加计数，后续 Heartbeat 服务应在串行处理写请求后观察更新并重启周期；计数为 uint32_t，自然回绕，不可用大小比较推断时间。重置整个对象表会恢复默认值并清零计数。
