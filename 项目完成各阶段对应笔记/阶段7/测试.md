### 1. Boot-up 和 Heartbeat

开发板复位后，上位机收到：

```
CAN-ID：0x701
数据：00
```

- `0x701 = 0x700 + 1`：节点 1 的 Heartbeat CAN-ID。
- `00`：Boot-up，表示节点刚启动。

随后收到：

```
0x701 / 7F
```

- `7F`：Pre-operational 状态。

### 2. NMT 切换到 Operational

上位机发送：

```
软件 ID：00 00 00 00
数据：01 01
```

对应 CANopen：

```
CAN-ID：0x000
数据：01 01
```

- 第一个 `01`：Start Remote Node。
- 第二个 `01`：目标节点 ID 为 1。

收到：

```
0x181 / 00
```

- `0x181 = 0x180 + 1`：节点 1 的 TPDO1。
- `00`：DI 当前值为 `0`。

```
0x281 / 00 00 00 00
```

- `0x281 = 0x280 + 1`：节点 1 的 TPDO2。
- 第 1、2 字节：AI1，`00 00` = 0。
- 第 3、4 字节：AI2，`00 00` = 0。

```
0x701 / 05
```

- `05`：Operational 状态。

### 3. SDO 读取 Heartbeat 周期

上位机发送：

```
软件 ID：00 00 06 01
数据：40 17 10 00 00 00 00 00
```

对应：

```
0x601 / 40 17 10 00 00 00 00 00
```

- `40`：SDO expedited Upload，读取对象。
- `17 10`：Index `0x1017`，小端序。
- `00`：Sub-index `0x00`。
- 后四字节暂时填 0。

收到：

```
0x581 / 4B 17 10 00 E8 03 00 00
```

- `4B`：成功读取 2 字节。
- `17 10`：返回对象 Index `0x1017`。
- `00`：Sub-index `0x00`。
- `E8 03`：数据，小端序为 `0x03E8 = 1000 ms`。
- 最后两个 `00`：未使用。

其他读取也按同样方式记录：

```
上位机 ID：00 00 06 01
数据：40 00 60 01 00 00 00 00
```

收到：

```
0x581 / 4F 00 60 01 00 00 00 00
```

- `4F`：成功读取 1 字节。
- `00 60`：Index `0x6000`。
- `01`：Sub-index `0x01`。
- 第 5 字节 `00`：DI 当前值为 0。

AI1：

```
上位机 ID：00 00 06 01
数据：40 01 64 01 00 00 00 00
```

收到：

```
0x581 / 4B 01 64 01 00 00 00 00
```

- `4B`：成功读取 2 字节。
- `01 64`：Index `0x6401`。
- `01`：Sub-index 1，即 AI1。
- `00 00`：AI1 当前值为 0。

AI2：

```
上位机 ID：00 00 06 01
数据：40 01 64 02 00 00 00 00
```

收到：

```
0x581 / 4B 01 64 02 00 00 00 00
```

- `02`：Sub-index 2，即 AI2。
- `00 00`：AI2 当前值为 0。

### 4. RPDO 写 DO，并用 SDO 回读

上位机发送：

```
软件 ID：00 00 02 01
数据：05
```

对应：

```
0x201 / 05
```

- `0x201 = 0x200 + 1`：节点 1 的 RPDO1。
- `05 = 0000 0101b`：bit0 和 bit2 为 1。

随后读取 DO：

```
软件 ID：00 00 06 01
数据：40 00 62 01 00 00 00 00
```

收到：

```
0x581 / 4F 00 62 01 05 00 00 00
```

- `4F`：成功读取 1 字节。
- `00 62`：Index `0x6200`。
- `01`：Sub-index 1。
- `05`：DO 对象已经写入成功。

### 5. 修改 Heartbeat 周期

上位机发送：

```
软件 ID：00 00 06 01
数据：2B 17 10 00 F4 01 00 00
```

对应：

```
0x601 / 2B 17 10 00 F4 01 00 00
```

- `2B`：expedited SDO Download，写入 2 字节。
- `17 10`：Index `0x1017`。
- `00`：Sub-index 0。
- `F4 01`：小端序为 `0x01F4 = 500 ms`。

收到：

```
0x581 / 60 17 10 00 00 00 00 00
```

- `60`：写入成功确认。
- `17 10 00`：返回被写入的对象地址。
- 后四字节为 0，不表示新的数据。

再次读取收到：

```
0x581 / 4B 17 10 00 F4 01 00 00
```

- `F4 01 = 500 ms`，说明写入已经生效。
- 后续 `0x701` Heartbeat 间隔约为 500 ms。

### 6. NMT Stop 和恢复

发送 Stop：

```
软件 ID：00 00 00 00
数据：02 01
```

- `02`：Stop Remote Node。
- `01`：目标节点 1。

收到：

```
0x701 / 04
```

- `04`：Stopped 状态。
- 节点仍发送 Heartbeat，只是状态字节变成 04。

发送 Start：

```
软件 ID：00 00 00 00
数据：01 01
```

- `01`：Start Remote Node。
- `01`：目标节点 1。

随后收到：

```
0x181 / 00
0x281 / 00 00 00 00
0x701 / 05
```

说明节点重新进入 Operational，并重新发布初始 TPDO。

### 7. SDO Abort

上位机发送：

```
软件 ID：00 00 06 01
数据：40 99 99 00 00 00 00 00
```

对应：

```
0x601 / 40 99 99 00 00 00 00 00
```

- `40`：读取对象。
- `99 99`：Index `0x9999`。
- `00`：Sub-index 0。

收到：

```
0x581 / 80 99 99 00 00 00 02 06
```

逐字节：

| 字节          | 含义                              |
| ------------- | --------------------------------- |
| `80`          | SDO Abort 响应                    |
| `99 99`       | Index `0x9999`                    |
| `00`          | Sub-index `0x00`                  |
| `00 00 02 06` | Abort code，小端序为 `0x06020000` |

`0x06020000` 表示对象不存在。这个测试证明节点能够正确返回非法对象的 SDO Abort 响应。
