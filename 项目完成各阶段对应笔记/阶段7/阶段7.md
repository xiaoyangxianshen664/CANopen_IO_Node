### 第三部分：专门学习 500 kbit/s 位时序

当前项目配置是：

```c
APB1       = 45 MHz
Prescaler  = 6
BS1        = 11 TQ
BS2        = 3 TQ
SJW        = 1 TQ
```

计算过程：

```
CAN 时钟 = 45 MHz
一个时间量子 = 45 MHz / 6 = 7.5 MHz
一个 bit = 1 + 11 + 3 = 15 TQ
波特率 = 7.5 MHz / 15 = 500 kbit/s
```

这部分要理解 `Prescaler`、`BS1`、`BS2`、`SJW` 和 APB1 时钟之间的关系，因为后面接 USB-CAN 分析仪时，波特率错误会直接导致没有 ACK。



### 第四部分：学习接收中断和环形缓冲区

再看：

[stm32f4xx_it.c](C:/Users/lolbo/CANopen_IO_Node/firmware/stm32f429/User/stm32f4xx_it.c)

重点是：

```c
void CAN1_RX0_IRQHandler(void)
{
    HAL_CAN_IRQHandler(&Can_Handle);
}
```



这个中断函数本身不解析 CANopen。它只是调用 HAL，随后 HAL 再进入：

```
HAL_CAN_RxFifo0MsgPendingCallback()
```

当前接收流程是：

```c
CAN 总线收到帧
    ↓
CAN1_RX0_IRQHandler()
    ↓
HAL_CAN_IRQHandler()
    ↓
HAL_CAN_RxFifo0MsgPendingCallback()
    ↓
HAL_CAN_GetRxMessage()
    ↓
HAL 帧头和数据转换成 can_frame_t
    ↓
放入 BSP 环形缓冲区
    ↓
CAN_ReceiveFrame() 取出
```

要特别理解为什么中断回调只做“取帧和入队”，不在中断里直接执行 SDO、PDO 或 NMT 业务。



### 第五部分：学习发送邮箱

接着学习：

```c
co_status_t CAN_SendFrame(void *user, const can_frame_t *frame)
```

重点看这段逻辑：

```
HAL_CAN_GetTxMailboxesFreeLevel()
HAL_CAN_AddTxMessage()
```

协议层只产生这样的帧：

```
can_frame_t frame;
frame.id = 0x181;
frame.dlc = 1;
frame.data[0] = ...
```

BSP 再转换成 HAL 的发送结构：

```
CAN_TxHeaderTypeDef header;
header.StdId = frame->id;
header.IDE = CAN_ID_STD;
header.RTR = CAN_RTR_DATA;
header.DLC = frame->dlc;
```

这里要理解：

```
CO_OK
```

只表示帧已经提交到 CAN 发送邮箱，不代表总线已经收到 ACK。

如果三个邮箱都满了，就返回：

```
CO_ERR_TX_BUSY
```
