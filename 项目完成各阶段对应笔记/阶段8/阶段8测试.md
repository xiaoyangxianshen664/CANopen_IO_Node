# 阶段 8：FreeRTOS 与真实 I/O 测试记录



### 一、测试目标

将 CANopen 协议栈接入 FreeRTOS 任务系统，并完成真实硬件输入输出验证：

```c
CAN 接收中断
    ↓
BSP 接收软件环形队列
    ↓
CanopenTask
    ↓
NMT / SDO / PDO / Heartbeat
按键、ADC
    ↓
IOTask
    ↓
对象字典
    ↓
TPDO 上报或 SDO 读取
RPDO 写入 DO
    ↓
CanopenTask
    ↓
DO 输出队列
    ↓
IOTask
    ↓
RGB 灯 GPIO
```



### 二、硬件连接

| 功能       | 引脚 | 说明                    |
| ---------- | ---- | ----------------------- |
| DI1 / Key1 | PA0  | 按键输入                |
| DI2 / Key2 | PC13 | 按键输入                |
| AI1        | PC3  | 电位器，ADC1 通道 13    |
| AI2        | PA4  | 温度传感器，ADC1 通道 4 |
| DO 红灯    | PH10 | RGB 红色                |
| DO 绿灯    | PH11 | RGB 绿色                |
| DO 蓝灯    | PH12 | RGB 蓝色                |

ADC 使用 ADC1 + DMA2 Stream0，采样原始范围为 0～4095，对象字典中的 AI 值按照项目约定编码为：

```
对象值 = ADC 原始值 × 8
```



### 三、FreeRTOS 任务架构

| 任务              | 优先级 | 主要职责                                              |
| ----------------- | ------ | ----------------------------------------------------- |
| `CanopenTask`     | 3      | 接收 CAN 帧、处理 NMT/SDO/PDO、推进心跳、维护对象字典 |
| `IOTask`          | 2      | 读取按键和 ADC，执行 RGB 灯输出                       |
| `MonitorTask`     | 1      | 监视 I/O 采样计数和任务运行状态                       |
| `DiagnosticsTask` | 1      | 保存 CAN 错误、FIFO 溢出、Bus-off 等诊断快照          |

任务间通信：

- CAN RX 中断 → BSP 环形接收队列 → `CanopenTask`
- ADC DMA 中断 → 任务通知 → `IOTask`
- `IOTask` → 输入采样队列 → `CanopenTask`
- `CanopenTask` → DO 输出队列 → `IOTask`
- 输入采样队列和 DO 队列长度均为 1，只保留最新数据，避免旧数据堆积。

CanopenTask` 是对象字典的唯一拥有者，`IOTask` 不直接访问对象字典，从而避免协议处理和硬件采样并发修改对象字典。



### 四、实机测试过程



##### 1. Boot-up 和 Pre-operational

开发板重新烧录并复位后，收到：

```c
0x701 / 00
```

表示节点启动完成。

随后持续收到：

```c
0x701 / 7F（//表示节点处于 Pre-operational 状态）
```





##### 2. NMT 启动

发送：

```c
can-id 0x000  //上位机输入00 00 00 00
数据帧01 01   //上位机输入01  01
```

节点进入 Operational，收到：

```
0x701 / 05
```

同时节点开始发送 TPDO：

```
0x181 / 00
0x281 / AI1 AI1 AI2 AI2
```

Heartbeat 持续稳定上报。





##### 3. DI 测试

观察 TPDO1：

```c
0x181 / 00
```

按下 PA0 对应的 Key1 后，数据变化为：

```c
0x181 / 01		//为上位机的接受帧
```

松开按键后恢复：

```c
0x181 / 00
```

说明真实按键输入已经通过 IOTask 更新到 `0x6000:01`，并由 TPDO1 正确上报。



##### 4. DO 测试

依次发送 RPDO1：

```c
0x201 / 01		//上位机填入 00  00 02 01 ，数据帧填入 01 
0x201 / 02		//上位机填入 00  00 02 01 ，数据帧填入 02 
0x201 / 04		//上位机填入 00  00 02 01 ，数据帧填入 04 
0x201 / 05		//上位机填入 00  00 02 01 ，数据帧填入 05 
0x201 / 00		//上位机填入 00  00 02 01 ，数据帧填入 00 
```

对应结果：

| 数据 | 灯状态     |
| ---- | ---------- |
| `01` | 红灯       |
| `02` | 绿灯       |
| `04` | 蓝灯       |
| `05` | 红灯和蓝灯 |
| `00` | 全部熄灭   |

五种状态均与预期一致，说明：

```
RPDO → 对象字典 → DO 输出队列 → IOTask → GPIO
```

整条链路正常。



##### 5. AI1 读取测试

发送：

```c
0x601 / 40 01 64 01 00 00 00 00		//上位机输入00 00 06 01 数据帧40 01 64 01 00 00 00 00
```

收到：

```
0x581 / 4B 01 64 01 00 49 00 00	    
```

AI1 对象值为：

```
0x4900 = 18688
```

对应 ADC 原始值约为：

```
18688 ÷ 8 = 2336
```

拧动 PC3 电位器时，TPDO2 和 SDO 读取值会随之变化。



##### 6. AI2 读取测试

发送：

```c
0x601 / 40 01 64 02 00 00 00 00		//上位机输入00 00 06 01 数据帧40 01 64 02 00 00 00 00
```

收到：

```
0x581 / 4B 01 64 02 F8 3C 00 00
```

AI2 对象值为：

```
0x3CF8 = 15608
```

对应 ADC 原始值约为：

```
15608 ÷ 8 = 1951
```

握住温度传感器时，AI2 数值发生变化，说明 PA4 的真实模拟量采集正常。





##### 7. TPDO2 自动上报

TPDO2 使用：

```
0x281
```

数据格式为：

```
Byte 0～1：AI1
Byte 2～3：AI2
```

测试现象：

- 拧动电位器时，前两个字节变化；
- 握住温度传感器时，后两个字节变化；
- 两路 AI 的变化方向和对应通道符合预期。

由于自动上报周期较快，读取单个 AI 时使用 SDO 读取进行确认。



##### 8. Heartbeat 稳定性

测试期间持续收到：

```
0x701 / 05
```

Heartbeat 状态保持 Operational，没有出现节点复位、停止或通信中断。



### 五、编译验证

Keil ARMCC V5.06 编译结果：

```
0 Error(s)
0 Warning(s)
```

四任务架构已成功烧录并完成实机回归。



### 六、测试结论

阶段 8 的以下内容已经完成并通过实机验证：

- `CanopenTask`
- `IOTask`
- `MonitorTask`
- `DiagnosticsTask`
- CAN RX 中断到协议任务的消息链
- ADC DMA 到 IOTask 的通知链
- 真实 DI 读取
- 真实 AI1、AI2 采集
- RPDO 控制真实 RGB 灯
- DI/AI 更新对象字典
- TPDO 自动上报
- Heartbeat 稳定运行
- FreeRTOS 多任务架构下的 CANopen 通信

目前 `MonitorTask` 和 `DiagnosticsTask` 还是阶段 8 的基础监测入口，主要负责计数和错误快照，还没有实现 EMCY 故障上报、安全输出和自动恢复。这部分属于阶段 9
