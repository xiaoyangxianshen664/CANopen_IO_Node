**整个项目要实现的事情**

```
CAN 上位机
    │
    │ 读取输入、控制输出、配置参数、管理节点
    ▼
CAN 总线
    │
    ▼
STM32 CANopen I/O 节点
    ├── 4 路 DI：读取按键/数字输入
    ├── 4 路 DO：控制 LED/数字输出
    └── 2 路 AI：读取 ADC 采样值
```

------

### **阶段 0：确定我们要做什么**

```
需求与方案
    │
    ├── 硬件
    │     STM32F429、CAN1、4 DI、4 DO、2 AI
    │
    ├── 通信
    │     经典 CAN、标准帧、500 kbit/s、默认节点号 1
    │
    ├── 对象地址
    │     DI、DO、AI、心跳周期分别用什么索引
    │
    └── 协议范围
          NMT、Heartbeat、expedited SDO、固定 PDO、EMCY
          暂不支持动态 PDO 映射、分段/块 SDO 等
```

这一阶段确定设计和边界，给后续代码提供依据。

------

### **阶段 1：节点基础信息、发送入口和接收分类**

```
co_core.c
    │
    ├── co_init()
    │     保存节点号、初始状态、发送函数、辅助数据地址
    │
    ├── co_frame_validate()
    │     检查 CAN-ID、DLC 和帧类型
    │
    ├── co_send()
    │     检查后调用发送回调
    │
    └── co_classify_rx()
          对已经取得的报文分类
                 ├── NMT
                 ├── SDO
                 ├── RPDO1
                 └── 无关帧
电脑测试
    ├── 构造报文 → co_send() → fake_tx() 记录模拟发送
    └── 构造“收到的报文” → co_classify_rx() → 检查分类
```

**此时没有硬件收发，也不执行 NMT、SDO、PDO 服务。**

------

### **阶段 2：建立对象字典和设备实际数据**

```
co_od.c：通用访问工具
    ├── find   找对象条目
    ├── read   检查后调用读回调
    └── write  检查后调用写回调
                     │
                     │ 操作
                     ▼
co_device_od.c：项目实际对象表
    ├── DI 状态
    ├── DO 命令
    ├── AI1、AI2 采样值
    ├── 心跳周期
    ├── PDO 通信与映射参数
    └── 设备身份、错误寄存器
```

对象内部的连接：

```
definitions[]：规则与默认值
         │
         │ 初始化
         ▼
entries[]：实际条目
         ├── 对象地址、类型、权限、范围
         ├── 读写回调
         └── user 指针
                  │
                  ▼
             fields[]：当前数据、写入次数
EDS
 └── 给上位机看的对象说明书
       描述对象地址、类型、权限、默认值、PDO 映射等
```

**此时能查找和读写对象数据，但还没有通过 CAN 请求来操作它们。**

------

### **阶段 3：NMT 管理节点状态**

```
上电初始化
    │
    ▼
发送 Boot-up
    │
    ▼
进入 Pre-operational
    │
    ▼
接收上位机 NMT 命令
    │
    ├── Start ───────────► Operational
    ├── Stop ────────────► Stopped
    ├── Enter Pre-op ────► Pre-operational
    └── Reset ───────────► 按复位类型执行恢复流程
```

与阶段 1 的连接：

```
co_classify_rx()：识别“这是 NMT”
                       │
                       ▼
NMT 服务：解析命令、执行状态切换
                       │
                       ▼
更新 node.state
```

**状态会决定哪些服务当前允许工作。**

------

### **阶段 4：Heartbeat 定期报告节点状态**

```
对象字典：0x1017 心跳周期
              │
              ▼
         心跳服务计时
              │
              │ 到期
              ▼
读取 node.state，组装心跳帧
              │
              ▼
          co_send()
              │
              ▼
       发送回调 → CAN 总线
              │
              ▼
上位机获知节点在线及当前 NMT 状态
节点 1 的例子
    CAN-ID = 0x701
    数据   = 当前 NMT 状态字节
```

**阶段 2 保存周期，阶段 4 根据周期产生报文。**

------

### **阶段 5：SDO 按对象地址进行读写**

```
上位机：“读取 0x6401:01”
              │
              ▼
        STM32 收到 CAN 帧
              │
              ▼
阶段 1：检查、识别为本节点 SDO 请求
              │
              ▼
SDO 服务：解析操作、索引、子索引和数据
              │
              ▼
阶段 2：查找对象，执行读取或写入
              │
              ▼
SDO 服务：生成正常响应或 Abort 错误响应
              │
              ▼
       co_send() → 上位机
读取 AI1 ─────► 返回采样值
写入 DO ──────► 更新输出命令
修改心跳周期 ─► 更新 0x1017
非法请求 ─────► 返回对应 Abort
```

**SDO 把“CAN 报文”和“对象访问”正式连接起来。**

------

### **阶段 6：PDO 按固定映射交换 I/O 数据**

```
上位机                           STM32 节点 1
   │                                  │
   ├── RPDO1：0x201，1 字节 ──────────► DO 命令
   │                                  │
   ◄── TPDO1：0x181，1 字节 ─────────── DI 状态
   │                                  │
   ◄── TPDO2：0x281，4 字节 ─────────── AI1 + AI2
```

PDO 服务负责：

```
PDO 服务
    ├── 检查当前是否 Operational
    ├── 按固定映射解释或组装数据
    ├── 检查接收长度和数据是否合法
    ├── 处理变化触发、事件周期与抑制时间
    └── 调用对象访问接口及发送入口
```

**PDO 报文不携带对象索引，双方通过预先约定的映射理解数据。**

------

### **阶段 7：接入 STM32 CAN 硬件**

此前在电脑上测试的协议代码，开始连接 CAN1 外设：

```
接收方向
CAN 总线
    ↓
STM32 CAN1 接收 FIFO
    ↓
驱动取出报文，转换成 can_frame_t
    ↓
协议层检查、分类、处理
发送方向
协议服务组装 can_frame_t
    ↓
co_send()
    ↓
STM32 发送回调
    ↓
CAN1 发送邮箱
    ↓
CAN 总线
```

**这里才真正把模拟发送回调换成硬件发送实现。**

------

### **阶段 8：接入 FreeRTOS 和真实 I/O**

```
输入采集
GPIO 按键状态、ADC 采样
          │
          ▼
应用层整理逻辑值和采样值
          │
          ▼
更新对象表中的 DI、AI
          │
          ├── SDO 读取
          └── TPDO 上报
输出控制
上位机发送 SDO / RPDO
          │
          ▼
协议服务更新 DO 命令
          │
          ▼
应用层读取 DO 命令
          │
          ▼
GPIO 输出电平变化
          │
          ▼
LED 状态变化
FreeRTOS
    ├── 协调协议处理、采集和输出
    ├── 通过队列/通知传递事件
    └── 保护共享数据，保证访问顺序
```

**此时上位机读到真实输入，也能控制真实输出。**

### **阶段 9：EMCY 与可靠性**

```
检测到故障
    │
    ├── 更新错误寄存器
    │
    ├── 根据策略处理安全输出
    │
    └── 生成 EMCY 报文
              │
              ▼
         CAN 上位机获知故障
故障解除
    │
    ▼
按恢复策略更新状态、错误信息和输出
```

这一阶段补齐故障上报、安全停机和恢复，避免只验证正常通信。
